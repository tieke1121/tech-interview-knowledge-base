# Linux 基础与生产排障

> [!NOTE] 案例性质说明
> 事故、数字与追问为教学推演。面经只用于确认考点；参考答案按官方资料整理。练习需记录自己的实际口述与验证结果。

## 1. 知识概述与业务价值

把机器当成同时处理很多任务的工作场所。排障先确定谁在等 CPU、内存、磁盘或其他服务，再选工具验证。重点联系 Java 进程、Flink 状态后端和 Doris 扫描。

## 2. 核心概念与关系

进程拥有地址空间与资源，线程共享进程的许多资源，各有执行上下文和栈。虚拟地址经映射访问物理页；文件缓存利用内存减少磁盘读取；文件描述符是进程访问打开文件、管道和套接字的入口。

## 3. 底层工作机制与设计哲学

调度器分配 CPU 时间，阻塞任务等待条件满足。内存压力可能引起回收与 I/O，磁盘排队又延长任务等待。一次服务变慢可能跨越多个层次，应把系统指标与请求时间线对齐。

## 4. 高频复杂业务场景实操与落地

假设 Flink 检查点从 20 秒增至 90 秒。先比较忙碌时间、反压、状态大小与检查点各阶段，再查本机磁盘、网络和远端存储；单看 CPU 会漏掉 I/O 等待。以下为 Linux 环境只读检查命令，按需安装 sysstat、lsof。

```sh
uptime
vmstat 1 5
iostat -xz 1 5
df -h
df -i
```

记录采样窗口及设备。vmstat 首行通常是开机以来平均值，后续才是采样间隔；iostat 首份报告也要区别累计值。macOS 原生命令及指标口径不同。

## 5. 生产异常故障深度排查与根因分析

CPU 高 → 找热点进程与线程 → 对照栈。CPU 低但等待长 → 查阻塞、I/O、限流。内存持续上涨 → 分堆、原生内存与缓存。写入失败 → 查空间、inode、权限与只读挂载。每一步记录支持或反驳假设的证据。

## 6. 技术选型对比、架构演进与成本ROI

增加资源可缩短等待，但若是无界队列或泄漏，需要修正增长来源。限制并发会降低峰值吞吐，却可能保护尾延迟。修改前记录业务吞吐和 P99，再在相近负载下比较。

## 7. 技术经理与架构师实战管控

为实时、批处理与回填约定资源预算。高风险操作前保留必要日志和恢复信息，先用限流、暂停非关键任务止损；变更后检查延迟、错误率与积压是否恢复。

下面按公开面经考点组织六题，具体追问由本库设计。来源说明列出原题依据与延伸范围，公开样本不足以估算出题频率。

## 9. 结构化深度参考答案

### 题目1　进程、线程与资源共享怎样影响 Java 服务？

#### 简洁回答

**求职者**　同一进程的线程共享堆和打开文件等资源，线程各有栈和执行上下文；共享数据需要同步。

#### 深入回答

**面试官**　线程越多吞吐越高吗？

**求职者**　线程增加会占用栈和调度资源，锁竞争或下游容量会形成上限。先看任务的 CPU 与等待比例、连接池容量，再给队列和线程数设上限。

#### 架构师/技术管理视角

把线程池拒绝、队列长度和处理时长纳入监控，压力测试验证过载时能否及时失败。

### 题目2　CPU 占用不高，负载很高，怎样查？

#### 简洁回答

**求职者**　Linux load average 包括可运行任务和不可中断睡眠任务，需结合核数及进程状态分析。

#### 深入回答

**面试官**　是否就能判定磁盘坏了？

**求职者**　还可能涉及远程文件系统或其他内核等待。用 vmstat、线程状态与 I/O 指标缩小范围，按同一时段比较，不能凭单个 load 值判定根因。

#### 架构师/技术管理视角

优先降低引起等待的批任务并发，验证关键服务是否恢复，再决定扩容或修复存储。

### 题目3　Java 堆未满，进程却被杀，为什么？

#### 简洁回答

**求职者**　进程总用量还包括原生内存、线程栈和相关内存计费。容器限制可能早于堆上限触发。

#### 深入回答

**面试官**　退出码 137 就代表 OOM 吗？

**求职者**　137 通常表示 SIGKILL，也可能来自人为终止或停止超时。结合容器状态、内核日志和对应 cgroup 的 memory.events；计数需与故障时间及采样增量对应。

#### 架构师/技术管理视角

为堆外和运行时留余量。不要把堆上限直接等同于容器额度；恢复前确认是否持续泄漏。

### 题目4　文件删了，磁盘空间为什么没释放？

#### 简洁回答

**求职者**　若最后一个文件名已删除，但进程仍打开该文件，空间要等最后相关引用关闭才可回收。

#### 深入回答

**面试官**　怎么找到占用者？

**求职者**　先对比 df 与 du，结合 lsof +L1 找已删除但仍打开的文件；也检查挂载边界。通过应用支持的日志重开或受控重启释放，避免盲目清空业务文件。

#### 架构师/技术管理视角

规定日志轮转和保留期，报警同时覆盖容量、inode 与增长速度。

### 题目5　有空闲内存还需要关注 Page Cache 吗？

#### 简洁回答

**求职者**　文件缓存减少读取磁盘的次数，Kafka 与湖表扫描都可能受益。可回收缓存和可用内存要一起观察。

#### 深入回答

**面试官**　清空缓存能提升性能吗？

**求职者**　清空缓存可能让后续读取回到磁盘。区分缓存增长与匿名内存增长，观察回收压力、缺页和 I/O。单凭 free 很低无法断言内存泄漏。

#### 架构师/技术管理视角

压测明确冷缓存与热缓存条件，估算并发扫描对其他租户的影响。

### 题目6　怎样限制某个任务抢占 CPU？

#### 简洁回答

**求职者**　优先级影响竞争时的调度倾向，cgroup 可配置权重或时间配额。

#### 深入回答

**面试官**　宿主机空闲，任务也可能被限流吗？

**求职者**　可能。任务用完所属 cgroup 的 CPU 配额后会被节流。结合 cpu.max 与 cpu.stat 的节流计数增量，确认配额层级及负载。

#### 架构师/技术管理视角

调配额时同步观察吞吐和尾延迟；多个租户总预算与节点容量需一起规划。

技术机制的核对入口见本章官方资料。[Linux cgroup v2](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html) · [top 手册](https://man7.org/linux/man-pages/man1/top.1.html) · [unlink 手册](https://man7.org/linux/man-pages/man2/unlink.2.html)
