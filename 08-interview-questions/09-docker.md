# Docker 入门与 Java 容器排障

> [!NOTE] 案例性质说明
> 事故、数字与追问为教学推演。面经只用于确认考点；参考答案按官方资料整理。练习需记录自己的实际口述与验证结果。

## 1. 知识概述与业务价值

先掌握镜像、容器、网络、数据卷和资源限制。能解释 Java 服务如何启动、文件存在哪里、停止时发生什么，再把这些知识用于 Flink 与数据库测试环境。

## 2. 核心概念与关系

镜像提供启动所需文件与配置，容器是其运行实例。Linux 容器共享所在 Linux 环境的内核，namespace 隔离视图，cgroup 管理资源。macOS Docker Desktop 的 Linux 容器运行在 Linux 虚拟机中。

## 3. 底层工作机制与设计哲学

启动时组合镜像文件系统、可写层、挂载和进程配置。容器主进程退出会结束该实例的运行；再启动与删除重建是不同操作。容器可以有多个进程，需正确处理信号和子进程回收。

## 4. 高频复杂业务场景实操与落地

先对已存在的测试容器观察状态。把名称替换为自己的容器，输出日志时注意业务数据。

```sh
docker version
docker ps -a
docker inspect --format "{{json .State}}" interview-demo
docker inspect --format "{{json .Mounts}}" interview-demo
docker stats --no-stream interview-demo
docker logs --tail 50 interview-demo
```

预期能说出退出状态、挂载来源和瞬时用量。不存在该容器时会报错，应先从列表选取。本章命令为操作指南，实际实验结果需另记。

## 5. 生产异常故障深度排查与根因分析

启动失败 → 查入口命令、架构、权限和依赖。无法访问 → 查容器内监听、网络成员与发布端口。数据丢失 → 查原挂载及重建参数。被终止 → 查退出码、OOM 状态、日志和停止动作。

## 6. 技术选型对比、架构演进与成本ROI

应用与数据库分别管理生命周期，数据落持久化挂载。多阶段构建保留运行依赖并减少最终镜像体积；固定可追踪版本并计划更新。选择 bind mount 要考虑宿主路径依赖，volume 要考虑备份和迁移。

## 7. 技术经理与架构师实战管控

为每个服务记录镜像版本、端口、数据位置、资源额度与停止时限。使用最小所需权限；升级前验证数据恢复，应用回滚还要确认数据库与配置兼容。

## 9. 结构化深度参考答案

### 题目1　容器化解决什么问题，和虚拟机有什么差别？

#### 简洁回答

**求职者**　镜像帮助固定应用依赖与启动方式。Linux 容器隔离进程视图并共享内核，虚拟机通常运行独立来宾内核。

#### 深入回答

**面试官**　容器内显示 Ubuntu，就有独立内核吗？

**求职者**　发行版用户空间与内核是不同层次。Linux 容器使用运行环境的 Linux 内核；Docker Desktop 在 Mac 上还包括虚拟机边界。

#### 架构师/技术管理视角

确认 CPU 架构、系统调用与权限依赖，交付时记录运行环境，不能只保存镜像名。

### 题目2　Docker 资源限制怎样影响 Java？

#### 简洁回答

**求职者**　CPU 和内存额度影响进程可用资源，Java 堆之外还需运行时与原生内存。

#### 深入回答

**面试官**　堆设为容器全部额度会怎样？

**求职者**　其余内存可能使总用量超限。结合 JVM 配置、容器状态和 cgroup 事件判断。CPU 配额耗尽通常表现为节流，需要观测吞吐与延迟。

#### 架构师/技术管理视角

根据负载测得预算和余量，对不同任务设额度并验证过载行为。

### 题目3　镜像拉不下来怎样查？

#### 简洁回答

**求职者**　按错误区分名称或标签不存在、认证、DNS、网络、证书和本地空间。

#### 深入回答

**面试官**　Mac 能运行，Linux 服务器启动却失败呢？

**求职者**　核对镜像平台与 CPU 架构、入口文件权限和启动日志。镜像拉取成功与应用兼容是两个验证点，多架构构建仍需要在目标环境测试。

#### 架构师/技术管理视角

版本留存与镜像仓库可用性纳入交付方案，发布记录保存可追踪的镜像摘要。

### 题目4　两个容器怎样通信？

#### 简洁回答

**求职者**　用户自定义 bridge 网络可让容器通过名称发现同网络中的服务。localhost 指向当前容器自己的网络空间。

#### 深入回答

**面试官**　Dockerfile 写 EXPOSE，宿主机就能访问吗？

**求职者**　EXPOSE 是端口声明，通常还需发布端口并确认进程监听的地址。容器内只绑定 127.0.0.1 时，外部通过容器网卡地址无法访问该监听。

#### 架构师/技术管理视角

按最小需要发布端口，本地测试可绑定宿主回环地址；认证与访问控制要一起验证。

### 题目5　删除容器后文件还能找回吗？

#### 简洁回答

**求职者**　可写层随容器删除而消失；持久化 volume 的生命周期独立，能否保留还取决于删除选项与卷类型。

#### 深入回答

**面试官**　重启和删除重建是否一样？

**求职者**　停止再启动同一容器通常保留可写层。重建需重新挂载原数据；bind mount 依赖宿主路径，tmpfs 属于临时内存存储。

#### 架构师/技术管理视角

记录目录与挂载映射，用测试数据验证重建和恢复，数据库还要采用应用一致的备份。

### 题目6　怎样让 Java 容器优雅停止？

#### 简洁回答

**求职者**　让主进程收到停止信号，停止接收新请求，给在途请求和必要持久化留出时间，再退出。

#### 深入回答

**面试官**　为什么停止超时后变成 137？

**求职者**　运行时可在等待期限后强制终止。检查入口脚本是否正确转发信号，优先使用 exec 形式启动程序；结合停止日志区分强杀与 OOM。

#### 架构师/技术管理视角

停止时间预算要匹配业务，外部写入依然需要幂等和恢复能力，验证中断时的最终结果。
