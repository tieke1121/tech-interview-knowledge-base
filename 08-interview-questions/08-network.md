# 网络基础与请求超时排障

> [!NOTE] 案例性质说明
> 事故、数字与追问为教学推演。面经只用于确认考点；参考答案按官方资料整理。练习需记录自己的实际口述与验证结果。

## 1. 知识概述与业务价值

从一次请求出发解释 DNS、连接、TLS、请求处理与响应传输。网络知识帮助判断 Flink 跨节点传输、Doris 结果返回和 Spring 接口慢在哪一段。

## 2. 核心概念与关系

DNS 把名称解析到地址信息；TCP 提供有序可靠字节流；TLS 提供加密及身份验证；HTTP 定义请求和响应语义。连接成功只是路径的一步，业务还要等待排队和执行。

## 3. 底层工作机制与设计哲学

TCP 通过序号、确认及重传等机制传送字节。接收方流控与网络拥塞控制限制不同的瓶颈。HTTP 应用仍需定义消息、业务状态与重试语义。批处理能减少应用请求开销，复用连接能减少建连成本。

## 4. 高频复杂业务场景实操与落地

对允许访问的测试端点采样，给连接和总耗时设置上限。

```sh
curl --http1.1 --connect-timeout 3 --max-time 10 -sS -o /dev/null \
  -w "dns=%{time_namelookup} connect=%{time_connect} tls=%{time_appconnect} first=%{time_starttransfer} total=%{time_total} code=%{response_code}\n" \
  https://example.com/
```

这些时间大多从开始累计。新建直连 HTTPS 请求可用差值粗分阶段；代理、重定向、连接复用会改变解释。首字节时间还含网络与发送开销，应结合服务端日志。

## 5. 生产异常故障深度排查与根因分析

解析失败 → 查 DNS 配置与缓存。建连失败 → 查监听地址、路由、防火墙和端口。TLS 失败 → 查证书、主机名及系统时间。首字节慢 → 查排队与服务执行。响应传输慢 → 查结果大小、客户端读取和链路质量。

## 6. 技术选型对比、架构演进与成本ROI

连接复用节省握手但需要管理空闲失效；大批次减少固定开销但增加等待和内存占用。选择超时与批次需要同时满足业务期限和下游容量。

## 7. 技术经理与架构师实战管控

统一调用链总时间预算，重试采用有界次数、退避和抖动。关键写接口明确幂等键、结果查询与重复响应。跨租户限制连接数和导出并发，监控重试放大。

## 9. 结构化深度参考答案

### 题目1　DNS 查询与缓存怎样影响服务访问？

#### 简洁回答

**求职者**　客户端通常先利用本地缓存，经递归解析器获取结果，缓存受 TTL 等策略影响。A 记录指向 IPv4 地址，CNAME 指向另一名称。

#### 深入回答

**面试官**　改了 DNS 为什么还有请求到旧服务？

**求职者**　解析器与应用缓存、已有长连接都可能保留旧目标。分别核对解析结果、进程连接与应用缓存策略，再规划新旧服务的重叠运行时间。

#### 架构师/技术管理视角

迁移前预留观察窗口，发布后按实际请求目的地验证，保持旧服务可回退。

### 题目2　TCP 握手与关闭为什么需要状态机？

#### 简洁回答

**求职者**　双方需要同步序号和连接状态；关闭时发送方向分别结束。

#### 深入回答

**面试官**　为什么关闭后有 TIME_WAIT？

**求职者**　它使旧连接的迟到报文与重传 FIN 得到处理。通常主动关闭方进入；数量多要结合连接创建速率、四元组和实际端口压力分析。

#### 架构师/技术管理视角

优先核对连接复用与空闲策略，参数调整要验证风险，避免把正常状态当故障。

### 题目3　TCP 粘包怎样处理？

#### 简洁回答

**求职者**　TCP 传送字节流，一次发送与一次读取的边界不保证对应。应用要定义消息长度或分隔规则。

#### 深入回答

**面试官**　读到了消息头但正文不完整呢？

**求职者**　保留接收缓冲，按协议继续读取，完整后再解析。长度字段设上限，处理非法长度和超时，防止无限缓冲。

#### 架构师/技术管理视角

用拆分头部、分段正文、多条合并和畸形输入验证解析器，并设置资源上限。

### 题目4　HTTP 和 HTTPS 怎样区分？

#### 简洁回答

**求职者**　HTTPS 在 TLS 保护下传输 HTTP，客户端验证服务端身份并协商密钥。

#### 深入回答

**面试官**　同一 IP 能承载多个 HTTPS 域名吗？

**求职者**　可以，通常通过 TLS SNI 选择证书，HTTP Host 或相应版本的 authority 信息选择应用。证书仍须覆盖请求主机名。

#### 架构师/技术管理视角

管理证书轮换和到期监控，排查时保留验证，避免关闭校验掩盖配置错误。

### 题目5　长连接与短连接怎样选择？

#### 简洁回答

**求职者**　重复请求通常可复用连接降低建连开销；连接池需要控制数量与获取等待。

#### 深入回答

**面试官**　连接池越大越好吗？

**求职者**　下游有容量上限，过多连接可能增加排队。核对获取连接时间、连接失效、代理空闲超时与服务端并发，按业务期限设置预算。

#### 架构师/技术管理视角

压测同时记录成功吞吐、P99 和超时率，限制低优先级调用保护关键业务。

### 题目6　接口超时如何判断执行结果？

#### 简洁回答

**求职者**　超时只说明调用方没有及时取得结果，服务端可能已经执行。

#### 深入回答

**面试官**　POST 可以自动重试吗？

**求职者**　要核对业务幂等契约。用业务请求 ID 绑定参数及结果，重复请求返回同一操作结果，冲突参数需拒绝；必要时查询后补偿。

#### 架构师/技术管理视角

以提交后响应丢失作为演练场景，检查副作用次数，避免多层无限重试。
